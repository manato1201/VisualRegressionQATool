Visual Regression QA Tool

アーキテクチャ & 技術ドキュメント

再現性を最大化した上でのシンプルなピクセル差分による回帰検知。SSIM等の知覚的差分アルゴリズムには頼らず、まず撮影を決定的にし、評価はシンプルに保つ。

撮影指示 → 撮影画像 → 基準画像 → 差分画像 → 評価結果 → DB
概要 システム構成 データモデル 単発差分実行 一括差分実行 PixelDiffEngine アラート CaptureAgent API仕様 セットアップ テスト

概要

設計書(VisualRegressionQATool_DESIGN.md)は Unity での決定的撮影(Phase 1-2)を含む5フェーズ構成だが、 本リポジトリは Phase 3〜5(基準画像管理+差分評価・DB永続化・アラート/ビューア)を FastAPI + SQLite のバックエンドと React 19 + Vite のフロントエンドで実装したもの。

Phase内容状態
Phase 1再現性制御レイヤー(Unity C#)対象外
Phase 2撮影パイプライン(Unity C#)対象外
Phase 3基準画像管理+差分評価実装済み
Phase 4DB永続化+履歴実装済み
Phase 5アラート+結果ビューア実装済み

機能一覧

  • 撮影指示(CaptureInstruction)管理
  • 撮影画像アップロード + checksumベースのdedupeBLOBストレージ
  • ReferenceStore昇格ワークフロー(承認前の画像は基準として使われない)
  • PixelDiffEngine(per_pixel_tolerance / max_diff_pixels / min_diff_region_pixels)
  • 単発 / 一括(バッチ)差分実行
  • first-bad-commitクエリ
  • IAlertSink抽象化(Noop / Webhook / GitHub Issue)
  • 差分ビューアWeb UI(サイドバイサイド / オーバーレイ)
  • CaptureAgent共通インターフェース(Unity/Houdini連携)

単発差分実行のシーケンス

sequenceDiagram
    actor User
    participant UI as React UI
    participant API as POST /api/diffs/run
    participant Engine as PixelDiffEngine
    participant Blob as BlobStore
    participant DB as SQLite
    participant Sink as IAlertSink

    User->>UI: 「差分実行」
    UI->>API: captured_image_id + diff設定
    API->>DB: get_captured_image / get_active_reference_image
    API->>Blob: read(captured), read(reference)
    API->>Engine: compare_bytes(tolerance, max_diff_pixels, min_diff_region_pixels)
    Engine-->>API: DiffResult
    API->>Blob: put(diff_image PNG)
    API->>DB: create_diff_image → create_evaluation_result
    alt verdict = fail
        API->>DB: find_open_alert_issue
        API->>Sink: notify_failure
        API->>DB: create_alert_issue
    else verdict = pass
        API->>DB: close_open_alert_issues
        API->>Sink: notify_recovery
    end
    API-->>UI: DiffRunResult

一括差分実行のシーケンス

1件の失敗が他の項目に影響しないことが要点。/run と /run-batch は共通ロジック _execute_diff_run() を共有する。

sequenceDiagram
    actor User
    participant UI as React UI
    participant API as POST /api/diffs/run-batch
    participant Core as _execute_diff_run()

    User->>UI: 複数選択→「まとめて差分実行」
    UI->>API: captured_image_ids[]
    loop 各ID
        API->>Core: 単発差分ロジック
        alt 成功
            Core-->>API: DiffRunResult
        else 失敗
            Core-->>API: DiffRunError
            Note over API: このitemのみ失敗記録、継続
        end
    end
    API-->>UI: results[]
    UI-->>User: "N件成功 / M件失敗"

PixelDiffEngineの判定フロー

min_diff_region_pixelsは類似度スコアではなく、厳密な画素差分マスクに対する連結成分ベースの後処理(ノイズ除去)である。

flowchart TD
    A[captured / reference バイト列] --> B{解像度一致?}
    B -- No --> C[ImageDimensionMismatchError]
    B -- Yes --> D[RGB各チャンネルの絶対差を計算]
    D --> E{差 > per_pixel_tolerance?}
    E -- No --> F[diffなし]
    E -- Yes --> G[diff_maskに記録]
    F --> H
    G --> H{min_diff_region_pixels > 1?}
    H -- No --> I[diff_pixel_countを集計]
    H -- Yes --> J[scipy.ndimage.labelで8連結ラベリング]
    J --> K[サイズ未満の塊を除去]
    K --> I
    I --> L{diff_pixel_count <= max_diff_pixels?}
    L -- Yes --> M[verdict = pass]
    L -- No --> N[verdict = fail]

アラートのライフサイクル

stateDiagram-v2
    [*] --> NoOpenAlert
    NoOpenAlert --> Open: fail かつ 既存openなし / notify_failure
    Open --> Open: fail かつ 既存openあり / 重複防止
    Open --> NoOpenAlert: pass / notify_recovery して close
    NoOpenAlert --> NoOpenAlert: pass（何もしない）
