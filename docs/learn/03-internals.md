# 3. 内側のしくみ

講義(第 1〜4 回)で扱った核のほかに、**アップロード・差分実行の細部・認証と管理画面・フロントエンド**を説明します。

## 1. アップロード(`routers/captures.py`)

1. 指示が存在するか(なければ 404)。
2. ファイルを**メモリに読み込み**、Pillow で開く(開けなければ 400)。
3. **PNG に正規化して再エンコード**してからハッシュを取る: 同じピクセルを `.png` と `.jpg` で別々にアップロードしても、**中身が同じなら 1 つにまとまる**(クライアントが付けた拡張子に、重複排除を左右されない)。
4. `BlobStore.put` → `captured_image` に 1 行(`dedup_hit` を返す)。

> **気をつけること**: ファイル全体をメモリに読むので、**巨大な画像**で、メモリを使い切りうる。コードの上では、アップロードのサイズ上限は**見当たらない**(前段のリバースプロキシで制限する想定。要確認)。JPEG は**不可逆**なので、PNG に直しても、元の圧縮のノイズは残る(許容誤差で吸収する)。

## 2. 差分実行(`routers/diffs.py` の `_execute_diff_run`)

講義[第 3 回](../lecture/03-history-flaky-alerts.md)の流れのとおり。細部:

- **`_load_pair`**: 撮影画像と、**その指示の有効な基準**を取る。基準がなければ 404。基準を `reference_image_id` で**指定**したときは、その基準が**同じ指示のものかは確かめていない**(別の指示の基準も使えてしまう。意図した柔軟さかは未確認)。
- **しきい値は、毎回リクエストで渡す**(`per_pixel_tolerance`・`max_diff_pixels`・`min_diff_region_pixels`)。指示に保存されたものではなく、**`diff_image` に結果と一緒に保存**される。
- **一括実行**(`run-batch`): 複数の撮影画像を順に実行。**1 件の失敗(404・サイズ違い)が、他に影響しない**(件ごとに結果かエラーを返す)。
- **プレビュー**(`preview`): 比較は同じだが、**何も保存しない・通知しない**。しきい値を動かして「判定がどう変わるか」を試す(しきい値ラボ)。デバッグ機能なので、本番では既定で**無効**。
- **エラーの返し方**(`_DiffRunError`): サイズ違い・壊れた画像は **422**、撮影画像・基準が無いのは **404**、基準が指す撮影画像や BLOB が無いのは **500**。一括実行では、これらが**件ごと**に返る。
- **`reconcile_flaky_verdicts`** は、評価のたびに走る(同じ版の pass と fail の混在を flaky に)。**過去の判定を書き換える**ので、flaky になった後で、元の pass / fail は読めない。

## 3. 削除のルール(`repository.delete_captured_image`)

基準に昇格済み・差分履歴に含まれる画像は**削除できない**(409)。**鎖が途切れない**ように。削除できたときは、**同じ中身(ハッシュ)を指す行がほかに無い場合だけ**、BLOB のファイルを消す(重複排除の裏返し: 1 つのファイルを、複数の行が共有しうる)。

## 4. 認証・役割・監査

構造は、ToolOrchestrationHub(別リポジトリ)の認証・役割・監査と同じ型です。

| 役割 | できること |
|---|---|
| `viewer` | 見る(ダッシュボード・差分・画像) |
| `operator` | viewer + 撮影のアップロード・指示の作成・差分の実行 |
| `admin` | operator + **基準への昇格**・**撮影の削除** |

- 既定は**認証なし**(`VRQA_AUTH=off`)。Host の許可リスト(DNS rebinding)と、変更操作の Origin の検査は**常に**効く。**`VRQA_CORS_ORIGINS` の `*` は拒否**。
- `VRQA_AUTH=required` で、`/api/health`・`/api/auth/me`・`/api/auth/login` 以外は viewer 以上。**ユーザーが 0 人なら起動しない**(fail-closed)。
- API キーは**ハッシュだけ**保存。ブラウザでは HttpOnly・SameSite=Strict のクッキー(`<img>` はヘッダを付けられないため)。
- **監査ログ**: 変更系・拒否(401・403)・ログイン・ログアウトを JSON Lines で。**本文・キー・クッキー・クエリは記録しない**。5 MB で `.1` に退避。admin だけ `GET /api/auth/audit` で読める。

### 管理画面の分離(2026-11-11)

基準への昇格と撮影の削除(admin の操作)は、差分ビューア(`index.html`)ではなく、**別エントリー・別バンドルの `admin.html`**(`src/admin/`・`src/adminApi.ts`)にあります。

- 差分ビューアのコードには、**昇格・削除の API 呼び出しも、操作の部品も入っていない**(`test_admin_split_frontend.py` が確認)。
- ただし、**UI は静的配信**なので、バンドルの配布を絞って守っているのではない。**守っているのは、サーバーが昇格・削除を admin に限る(403)こと**。分離は、**誤操作を減らす**ための UI の整理。

## 5. フロントエンド

- **API の型**は `types.ts`(バックエンドの `models.py` の写し)。**API を変えたら、両方を直す**(自動生成ではない)。
- **差分ビューア**(`DiffViewer.tsx`・約 600 行)は、4 つの表示(差分・並べて・スライダー・点滅)、背景(白・黒・市松)、ズーム。**判定は色だけに頼らず**「✓ 合格 / ✕ 不合格 / — 未検査」の文字を添える。差分のピクセルは**固定のマゼンタ**(バックエンドの `HIGHLIGHT_COLOR` と**同期**が要る。`diffClusters.ts` の `DIFF_HIGHLIGHT_RGB`)。
- **昔の差分画像(赤)**も読めるように、フロントは赤とマゼンタの両方を認識する(過去に作られた差分が、そのまま見えるように)。
- **トースト**は、`GET /api/alerts/toasts?since_id=` を**ポーリング**(`ToastStack.tsx`)。
- **画像のピクセル値の取得**(スポイト)は、`<img crossorigin>` で読む。そのため、API の画像エンドポイントは `Vary: Origin` を返す(同じ URL を、普通の `<img>` と CORS の `<img>` の両方で読むと、ブラウザのキャッシュが取り違える)。
